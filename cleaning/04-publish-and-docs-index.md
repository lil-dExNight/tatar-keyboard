# Публикация и индекс документации — ревизия текстов

Область: `docs/PUBLISH-CHECKLIST.md` (1939 строк / 197 КБ), `docs/README.md`
(515 строк / 51 КБ), `docs/CLEANUP.md` (101 строка / 8,4 КБ), каталог
`docs/cleanup/` (6 PNG, ~353 КБ). Всё прочитано целиком; факты сверены с кодом
(`app/build.gradle`, `CompositePrefixComputer.kt`) и деревом (`ls docs/`,
`grep` перекрёстных ссылок, `git log`).

## Итог

Диагноз: **`PUBLISH-CHECKLIST.md` — самый запущенный файл проекта.** Это не
чек-лист, а свалка истории 20+ релизов: ~460 строк вложенных «Retargeted /
Перецелено» блоков (по одному на каждую версию от 3.6.0 до 1.5.0) плюс ~900
строк «Историческая запись» и «Evidence»-таблиц по каждой версии 1.2.0–1.8.4 —
всё это дублирует `docs/archive/apk-audits/APK-AUDIT-*.md`. Критично: **шапка
таргетирует v3.6.0, а сам пошаговый гейт (разделы 1–7, все чекбоксы, хеши
коммитов, evidence-таблицы) до сих пор про v1.8.3/v1.8.4** — «живая» процедура
на 21 релиз устарела. `README.md` — раздутый индекс: 418 строк на «живые
документы» с многострочными пересказами миссий (даты, счётчики тестов, номера
гейтов), тег «канонический английский» повторён 20 раз, 3 записи всё ещё
помечены «Uncommitted» для миссий, вышедших в релизе 2.0.0/2.0.1. `CLEANUP.md`
и `docs/cleanup/` — закрытый отчёт («МЕЛКИЕ ДОЛГИ ЗАКРЫТЫ»), место которому в
архиве.

Находки по категориям: [STALE] 6 (в т.ч. 1 критическая — тело чек-листа), [OVERLONG]/[DUP]
крупных блоков 8 (совокупно ~1400 строк PUBLISH-CHECKLIST + ~340 строк README),
[SLOP] 9 повторяющихся рефренов (17 + 8 + 8 + 10 + 7 + 5 повторов), [AGENT] 5,
[JARGON] системно во всех трёх файлах, [DELETE] 2 (CLEANUP.md + каталог cleanup/).

Топ-3 действия:
1. **Переписать `PUBLISH-CHECKLIST.md` в одну страницу** (шаблон ниже): версионно-независимая процедура + один блок текущего кандидата; всю историю релизов удалить (она уже есть в `APK-AUDIT-*.md`). Файл 1939 → ~90 строк.
2. **Сжать `README.md`** до одной строки на документ, снять тег «канонический английский», починить 3 «Uncommitted», выделить закрытые отчёты в раздел «Архив на верхнем уровне» (22 `APK-AUDIT-*.md` в корне `docs/` — это архив, а не живые доки).
3. **Перенести `CLEANUP.md` + `docs/cleanup/` в `docs/archive/`** (закрытый отчёт; сослаться на новый путь в 5 файлах, см. таблицу).

## Системные паттерны

1. **«Append-only живой документ».** И `PUBLISH-CHECKLIST.md`, и `README.md`,
   и `CLEANUP.md` растут дописыванием сверху/внутрь без вычистки старого. Правило
   массовой чистки: живой документ хранит **только текущее состояние**; всё
   «на дату X» уходит в отдельный отчёт (`APK-AUDIT-*`, `CHANGELOG`) и в живом
   доке заменяется одной ссылкой. Для чек-листа — «один блок кандидата», для
   индекса — «одна строка на файл».

2. **Захардкоженные дрейфующие числа.** Счётчики тестов (186→…→913→1927),
   размеры APK, SHA-256, гейты «13/13…19/19», холодные старты — вписаны в
   десятках мест. Правило: в живых доках чисел-снимков не держать; писать
   «сверять по выводу `release_check.sh` / `app/build.gradle`». Числа-снимки —
   только в датированных отчётах (там они история и не переписываются).

3. **Агентно-миссийная лексика в пользовательских доках.** «оператор»,
   «диспетчер», «миссия», «досье», рассказы про сессии/окно контекста/«отказы
   шлюза». Правило: чек-лист и индекс пишутся для будущего мейнтейнера в
   императиве действий; процессные артефакты («что делал агент») удаляются.

4. **Внутренние коды без расшифровки** (`D1`, `E5c`, `K=4`, `T7`, `O1–O8`,
   `S1–S9`, `F1–F17`, `P7-2`). Правило: в живых доках заменять человекочитаемым
   описанием; коды оставлять только внутри отчётов, где они введены.

5. **Повтор одной мысли дословно.** «upgrade path порван» ×17, «нужен бэкап» ×8
   и т.д. — следствие копирования блоков. Правило: инвариант формулируется один
   раз в разделе «Риски/подпись»; удаление дублирующих пластов убирает повторы
   автоматически.

6. **Дублирование отчёт↔индекс↔чек-лист.** Одна волна релиза описана трижды: в
   `APK-AUDIT-<ver>.md`, в шапке `PUBLISH-CHECKLIST.md` и в записи `README.md`.
   Правило: канон — `APK-AUDIT`/`CHANGELOG`; чек-лист и индекс только ссылаются.

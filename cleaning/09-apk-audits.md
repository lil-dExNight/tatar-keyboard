# docs/APK-AUDIT-*.md (корень docs/) — ревизия текстов

Область: 22 файла `docs/APK-AUDIT-*.md` в корне `docs/` (1.9.5 … 3.6.0),
2 490 строк, ~185 КБ. Более ранние (1.3.0 … 1.9.4 + 2026-08-18) уже лежат в
`docs/archive/apk-audits/` — прецедент архивации существует. Прочитаны все 22
файла целиком. Проверки по коду: `app/build.gradle` → versionCode **43**,
versionName **3.6.0** (совпадает с последним аудитом); `CELL_COUNT = 3`
(`SuggestionStripState.kt:171`, `CompositePrefixComputer.kt:363`) — полоса
сейчас 3 ячейки; аудит 3.6.0 это отражает верно, а 3.3.0/3.4.0/3.5.0 описывают
4 ячейки и live-превью глайда как «отгруженное» (сейчас реверт).

## Итог

Диагноз: это **не мусор, а честные, точные снимки на релиз** — но их формат
раздут и держится в живом `docs/` целой лентой из 22 файлов, хотя 60–70 %
каждого — повторяющийся boilerplate (подпись, разрешения, «в стор ничего не
ушло», гейт-таблица, «на устройстве ничего не переинфлируется»). Главный ответ
оператору: **не нужно** хранить полный многосекционный отчёт на каждый релиз.
Уникальны в каждом лишь три вещи — CRC32-дельта записей архива, разбор
«что переинфлируется при обновлении», указатель на девайсные свидетельства;
всё остальное уже выдаёт `release_check.sh --full` машинным блоком
`RESULT|PASS/FAIL`.

Находки по категориям: **DELETE/перенос** — 20 файлов в архив (1.9.5 … 3.5.0),
1 объединить (3.1.1 → 3.1.0), 1 оставить живым (3.6.0); **DUP** — ~9 повторов
структуры × 22 файла; **AGENT** — 6 мест (fresh agent/orchestrator, «recorded
honestly», «operator may amend», нарратив «repro copy deleted»); **SLOP** —
~12; **JARGON** — сплошь коды миссий без расшифровки; **LANG** — смена языка
RU→EN на 2.0.0 без причины + опечатка «ассекта»; **STALE** — вкраплённые
счётчики тестов/размеры, дрейфующие от файла к файлу.

Топ-3 действия:
1. Ввести короткий шаблон аудита (~15 строк, см. «Системные паттерны») и
   оставить живым только текущий релиз; `release_check.sh --full` — источник
   гейтов, аудит не дублирует счётчики.
2. `git mv` 20 закрытых аудитов (1.9.5 … 3.5.0) в `docs/archive/apk-audits/`
   рядом с 1.3.0 … 1.9.4; поправить индекс `docs/README.md` и ссылки.
3. Вычистить агентные артефакты (P1-таблица ниже) до любого переноса —
   переносим уже чистое.

## Системные паттерны

Повторяющиеся проблемы (одинаковый текст в большинстве из 22 файлов). Правило
общее: **вынести инвариант в один живой источник (шаблон/README/release_check),
из аудита убрать.**

1. [DUP] **«## Одной таблицей» — дублирующая kitchen-sink таблица** (RU-серия
   1.9.5–1.9.12): `1.9.5:7`, `1.9.6:8`, `1.9.7:10`, `1.9.8:10`, `1.9.9:9`,
   `1.9.10:10`, `1.9.11:10`, `1.9.12:12`. Строки cert / permissions /
   compileSdk-targetSdk-minSdk / no-INTERNET / «Воспроизводимость» /
   «Ради чего версия» повторяются дословно. Правило: в шаблоне оставить
   4 поля (размер, SHA-256, версия, дельта); инварианты (одна подпись,
   `[VIBRATE]`, нет INTERNET, SDK) — гарантируются `release_check.sh`, в
   аудите не повторять.

2. [DUP] **«## Подпись и разрешения» с shell-выводом** — блоки
   `apksigner verify --print-certs` + `aapt2 dump permissions` вставлены
   целиком в каждый RU-аудит (1.9.5–1.9.12). Идентичный сертификат
   `98ca6feb…42ad`. Правило: удалить блоки — это гейт `artifact.signature` /
   `artifact.permissions`, не текст для чтения.

3. [DUP][AGENT] **«## Чего в этом аудите нет» — повтор дословно**: «PSS/старт
   не мерены», «Живого телефона нет — все числа эмуляторные», «В стор ничего
   не ушло. Ни `git push`, ни тега наружу». Места «В стор…»: `1.9.5:141`,
   `1.9.6:226`, `1.9.7:98`, `1.9.8:126`, `1.9.9:140`, `1.9.10:139`,
   `1.9.11:126`, `1.9.12:128`. «Живого телефона нет»: `1.9.5:137`, `1.9.6:222`,
   `1.9.7:97`, `1.9.8:125`, `1.9.9:139`, `1.9.10:138`, `1.9.11:122`,
   `1.9.12:127`. Правило: «push/тег/публикация — оператор» уже в AGENTS.md;
   из аудита убрать. Реально открытые пункты — одной строкой «Открытое».

4. [SLOP] **«— the same key of the whole line» / «— тот же ключ всей
   линейки»** в строке Signature каждого файла: `1.9.14:12`, `1.9.15:12`,

### Предлагаемый шаблон короткого аудита (замена)

`release_check.sh --full` уже покрывает: сборку, JVM/python-тесты, lint,
no-internet, размер, пины ассетов, эмодзи/дерево-ассеты, разрешения, подпись,
версию, changelog, дельту к предыдущему — машинным блоком `RESULT|PASS/FAIL`.
Аудит НЕ должен это дублировать. Уникальная ценность аудита — только то, чего
скрипт не считает: пофайловая CRC32-дельта и разбор переинфляции. Отсюда
шаблон (~15 строк):

```
# APK-AUDIT <ver> (versionCode <n>) — <дата>

Артефакт: dist/tatar-keyboard-<ver>.apk, <размер> Б, SHA-256 <hash>.
release_check.sh --full — OVERALL PASS <k/k> (счётчики — в выводе скрипта).
```

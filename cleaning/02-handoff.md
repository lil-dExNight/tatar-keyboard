# HANDOFF.md — ревизия текстов

## Итог

`HANDOFF.md` — это **append-only журнал из 43 записей `# HANDOFF —`** (2254 строки, 155 КБ),
где каждая запись это датированный снимок очередного релиза/«волны» от 3.6.0 (сверху) до 1.9.7
(снизу). **Живой является ровно одна — верхняя (строки 1–45)**; остальные 42 (строки 47–2254,
≈97 % файла) — чистая история, уже полностью зафиксированная в git (97 коммитов на этот файл,
включая релизные `chore: release …`) и в `CHANGELOG.md` (132 КБ, разделы `[3.6.0]…[1.9.x]` в
чистой пользовательской форме). AGENTS.md (стр. 98) и `docs/README.md` (стр. 5) объявляют файл
«актуальным состоянием проекта» — значит, файл нужен, но **как экран текста, а не как летопись**.

Диагноз: тотальный [DUP] с git и CHANGELOG + сплошной [AGENT]/[SLOP]/[JARGON]. Находки по
категориям: **DUP — 42 записи целиком** (весь корпус ниже строки 47); **AGENT — ~40 повторов**
(«UNCOMMITTED; commits are the operator's» ×8, «gh is pull-only» ×10, «operator» 67 раз, счётчики
тестов/гейтов/SHA-256 55 раз); **JARGON — 325 совпадений** мисси-кодов (S8, O7, T7, E5c, P7-2,
SIZE-3, DEV-3…) без расшифровки; **SLOP — ≥8** («earned its keep» ×2, «centerpiece» ×2, «the mmap
witness that caught a regression», «fail-closed» 10 раз); **STALE — заголовок верхней записи** +
десятки исторических утверждений (4-cell как текущее, «UNCOMMITTED» у уже выпущенного 3.6.0);
**LANG — граница языков** на строке ~1476 (выше английский, ниже русский).

Топ-3 действия:
1. **Свести файл к одной текущей записи (≤ 1 экран)** по шаблону из раздела «Целевая структура»;
   удалить строки 47–2254 целиком — их содержимое есть в git и `CHANGELOG.md`.
2. Исправить [STALE]-заголовок строки 1: запись помечена «UNCOMMITTED», хотя git показывает
   `805155a4 chore: release 3.6.0` — волна выпущена и затегирована.
3. Ввести правило: HANDOFF перезаписывается (не дополняется). История живёт в git/CHANGELOG.

## Правки

Поскольку проблема системная (весь файл — один антипаттерн), ниже — **представительные цитаты по
категориям** с реальными строками; однотипные повторы свёрнуты в паттерн + список мест. Главная
правка (удалить строки 47–2254) покрывает большинство находок разом.

### Верхняя запись (строки 1–45) — единственная живая, но требует переписывания

- `HANDOFF.md:1` — [STALE][AGENT] — «# HANDOFF — strip UX revert wave (2026-09-29, **UNCOMMITTED**)» —
  заголовок говорит «не закоммичено», а тело (стр. 24) и git (`805155a4 chore: release 3.6.0`)
  говорят «выпущено 3.6.0/43». Прямое противоречие. **P1.** Замена: убрать «UNCOMMITTED», заголовок —
  «Текущее состояние — 3.6.0 (versionCode 43), выпущено 2026-09-29».

- `HANDOFF.md:2-11` — [SLOP][OVERLONG] — «the pixel-level proof: the strip region is byte-identical
  mid-gesture in `build/device-uat-2026-09-29/revert/interactive/`… ~30 test files re-pinned… smoke
  probes re-derived to thirds». Внутренняя археология правки, а не состояние. **P2.** Замена: одна
  строка — «Полоса подсказок снова 3 ячейки; live-превью глайда во время свайпа убрано (поведение до 3.3.0)».

- `HANDOFF.md:13-19` — [AGENT] — «Gates: JVM **1920 tests / 202 suites / 0 failures**… independent
  verifier verdict SHIP (24 test files byte-identical…)». Счётчики тестов и «вердикт верификатора»
  внутри живого дока — дрейфующие числа + артефакт агентного процесса. **P1.** Замена: удалить блок;
  актуальные счётчики берутся прогоном гейтов, а не из текста.

- `HANDOFF.md:21-23` — [AGENT] — «**UNCOMMITTED; commits/release are the operator's** (the tree is
  version 3.5.0/42…)». Устарело (уже 3.6.0/43) и адресовано «оператору». **P1.** Удалить.

- `HANDOFF.md:24-33` — [OVERLONG][AGENT] — «CLOSED 2026-09-29 — released as 3.6.0 / versionCode 43…
  SHA-256 `df32bc31…`, v2-only, cert `98ca6feb…42ad`; the pack run twice is byte-identical;
  `release_check.sh --full` **19/19 PASS**… Operator remainders: GitHub Release via the web UI…».
  SHA-256, сертификат, «19/19», ручные шаги оператора — это релизный протокол, а не handoff. **P2.**
  Замена: «Выпущено как 3.6.0/43; артефакт в `dist/`, ассеты байт-идентичны 3.5.0».

### Историческое тело (строки 47–2254) — удалить целиком; ниже маркеры-образцы каждой болезни

**[DUP] — записи дублируют CHANGELOG.md и git.** Пример: `HANDOFF.md:1329-1377` («release 2.0.0
prepared») ⇄ `CHANGELOG.md` раздел `[2.0.0]`; `HANDOFF.md:459-483` («3.1.0 was uninstallable, fixed
as 3.1.1») ⇄ `CHANGELOG.md` `[3.1.1]` + коммит `a5b69776 fix: release_pack…`. Все 42 записи — этот
случай. **P1.** Действие: удалить строки 47–2254.

**[AGENT] — «UNCOMMITTED; commits are the operator's»** — повтор в каждой волне:
`HANDOFF.md:179`, `:238`, `:306`, а также :21, :51-52, :485-487. Плюс «gh is pull-only» ×10
(`:365,:410,:456,:812,:867,:906,:961` и др.), «entry of the day» (`:459,:485,:545,:683`). Всё это —
следы агентного конвейера, не состояние продукта. **P1.** Удалить вместе с телом.

**[JARGON] — 325 мисси-кодов без расшифровки.** Образцы: `HANDOFF.md:47-84` (O1–O8, S1–S9),
`HANDOFF.md:963` («ROADMAP Phase 7… p95 3.39 ms»), `HANDOFF.md:1079` («T7/P5a shipped, P5b/P6
rejected»), `HANDOFF.md:121` («O7: the mmap witness»), E5c/D1/F3/F5 по всему тексту. Понятны только
участникам «миссий». **P1.** Удалить вместе с телом (в живой записи кодов быть не должно).

**[SLOP] — риторика и самолюбование:**
- `HANDOFF.md:51` и `:110` — [SLOP] — «S8… **earned its keep**: three real holes found and fixed» —
  оценочный пафос. **P2.** В CHANGELOG уже есть нейтральная формулировка — здесь удалить.
- `HANDOFF.md:84` и `:121` — [SLOP] — «O7: **the centerpiece**» / «**The centerpiece — O7: the mmap
  witness that caught a regression.**» — драматизация рабочего факта. **P2.** Удалить.
- `HANDOFF.md:121-135` — [SLOP][OVERLONG] — весь абзац про «mmap witness», «over its bound»,
  «per-byte absolute `MappedByteBuffer.get`… two worker-confined scratches (≤ 1 107 B each)» — сюжет
  о том, как агент ловил регрессию. **P2.** Удалить (суть уже в `CHANGELOG.md [3.5.0]` одной строкой
  «Faster dictionary reads… p95 5.19 ms → 1.72 ms»).

**[STALE] — исторические утверждения, противоречащие текущему коду:**
- `HANDOFF.md:330,343,357` — [STALE] — «**Four-cell strip** — CELL_COUNT 3 → 4 end to end»,
  подано как достижение 3.3.0. В коде `CompositePrefixComputer.kt:363` `CELL_COUNT = 3`, реверт
  зафиксирован (`TatBigrPrefixIndex.kt:183`). Читателя, севшего в середину файла, это дезинформирует.
  **P2.** Снимается удалением тела; в живой записи держать только «3 ячейки».
- `HANDOFF.md:963-1011` — [STALE] — вся Phase-7-запись с «p95 50.027 ms… FAILS the ≤ 5 ms gate»,
  затем reconciliation-сноска сверху про «PASSES p95 3.39 ms». Двойной устаревший слой. **P1.** Удалить.

**[LANG] — смена языка без причины на границе истории:**
- `HANDOFF.md:1476` и ниже — [LANG] — с записи «# HANDOFF — релиз 1.9.15…» текст переходит на
  русский, тогда как записи 3.x (стр. 1–1475) — на английском. Один файл, два языка, разделённые
  датой. **P3.** Снимается удалением тела; живая запись — по-русски (правило AGENTS.md).

**[OVERLONG] — гейт-таблицы в каждой записи.** Образцы: `HANDOFF.md:900-907`, `:955-961`,
`:1264-1275`, `:1508-1517`, `:1725-1735` — идентичные по форме таблицы «Гейт | Результат» с
дрейфующими числами тестов (1007, 1085, 1105, 1235, 1534, 1691, 1826, 1911, 1920…) и SHA-256.
Это протокол прогона, не handoff. **P1.** Удалить вместе с телом.

## Системные паттерны

1. **Append-only летопись вместо живого дока.** 43 записи, растущие вниз; актуальна одна.
   *Правило:* HANDOFF — это «где мы сейчас», а не «как мы сюда пришли». Перезаписывать при каждой
   волне, историю оставлять git и `CHANGELOG.md`. Удаление строк 47–2254 закрывает ~95 % находок.

2. **Числа-снимки, которые дрейфуют.** Счётчики тестов, размеры APK, SHA-256, «N/N PASS» вшиты в
   текст десятками (55 SHA-256, счётчики в каждой таблице). *Правило:* в живом доке не хранить чисел,
   получаемых прогоном. Хочешь число — запусти гейт. В CHANGELOG числа допустимы как факт релиза.

3. **Агентная адресация и процессные пометки.** «UNCOMMITTED», «commits are the operator's»,
   «gh is pull-only», «independent verifier verdict SHIP», «entry of the day». *Правило:* handoff
   описывает продукт, а не рабочий процесс ИИ-сессии и не то, что должен нажать оператор.

4. **Мисси-коды как язык изложения.** O7, S8, E5c, T7, P5b, SIZE-3 — 325 раз, без расшифровки.
   *Правило:* в живом доке — человеческие формулировки; коды миссий живут в своих отчётах `docs/`.

5. **Пафос вокруг рутины.** «centerpiece», «earned its keep», «the witness that caught a regression»,
   ритуальный «fail-closed». *Правило:* факт без оценочной надстройки.

## Целевая структура короткого HANDOFF (≤ 1 экран)

Предлагаемый шаблон вместо всех 2254 строк — переписывается целиком при каждой волне:

```markdown
# HANDOFF — текущее состояние

**Версия:** 3.6.0 / versionCode 43, выпущено 2026-09-29 (тег `v3.6.0`).
Артефакт в `dist/` (git-ignored). Ассеты байт-идентичны 3.5.0.

## Что в дереве сейчас
- Полоса подсказок: 3 ячейки. Live-превью глайда во время свайпа отключено (подсказки — на подъёме пальца).
- Всё закоммичено и запушено; `main` == `origin/main`.

## Как проверить, что всё зелёное
Прогнать гейты из AGENTS.md (JVM + python + lintRelease + check-no-internet + размер APK).
Числа тестов/APK намеренно здесь не фиксируются — они дрейфуют, смотри вывод прогона.

## Открытые хвосты (только незакрытое)
- Публикация GitHub Release: ручной шаг (веб-UI), `gh` на этой машине pull-only.
- Замеры release-scale frame/PSS не автоматизированы.
- `tatar-keyboard-release.jks` — секрет вне репозитория.

## Где история
Полная летопись релизов — `CHANGELOG.md` и `git log`. HANDOFF не ведёт историю.
```

Ориентир: ≤ 30–40 строк. Всё, что было ниже строки 47, уже покрыто `CHANGELOG.md` и git —
переносить не нужно, достаточно удалить.

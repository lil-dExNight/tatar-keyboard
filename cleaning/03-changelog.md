# CHANGELOG.md — ревизия текстов

## Итог

`CHANGELOG.md` — 915 строк / 132 КБ / 43 записи версий (1.0.0 → 3.6.0). Верхняя запись
`[3.6.0]` / versionCode 43 соответствует `app/build.gradle` (проверено), «3 ячейки»
соответствует `CELL_COUNT = 3` в коде, удаление live-превью свайпа подтверждено
`metadata/*/changelogs/43.txt` — то есть **сам файл не устарел, он раздут**.

Главный диагноз: **это не пользовательский changelog, а «миссийный» лог разработки.**
Настоящий текст для пользователя уже есть и уже короткий — `metadata/en-US/changelogs/*.txt`
и `metadata/ru-RU/changelogs/*.txt` (по versionCode, 43.txt = 3.6.0, 2 строки). А в
`CHANGELOG.md` слито всё, что пользователю не нужно: **хэш ключа `98ca6feb…42ad` — 14 раз**,
boilerplate «нет INTERNET / только VIBRATE» — **~28 раз**, 6 записей с прямой пометкой
`developer-facing`, слово `operator/оператор` — 7 раз, дрейфующие счётчики (правила
профиля, «1 456 tests», «61 500 iterations», байты), коды миссий (SIZE-1/2/3, TATDICT
schema 2, LXX, class #5, phase 4, K = 4, H = 10 000, stage D) и ~25 ссылок на внутренние
`docs/`. Плюс файл **на середине переключается с русского на английский** (1.9.x — RU,
2.0.0+ — EN).

Находки по категориям: [SLOP] ~7 очагов, [AGENT] ~13 (operator ×7 + developer-facing ×6),
[JARGON] ~10 групп, [OVERLONG] системно (простыни-абзацы вместо буллетов), [DUP] ~42
строки чистого boilerplate (ключ + INTERNET), [LANG] 1 системный (двуязычие файла),
[STALE] по счётчикам — не факты о версиях, а «дрейфующие» числа. [DELETE] — нет: файл
завязан на релизный ритуал и на него ссылается ~15 доков.

**Топ-3 действия:**
1. Определить роль файла: либо чистый Keep-a-Changelog для людей (короткий, один язык,
   без хэшей/счётчиков/гейтов), а вся кухня уходит в `HANDOFF.md`/`docs/`; либо честно
   переименовать по смыслу и оставить как dev-лог — но тогда убрать из него пользовательскую
   риторику. Рекомендация ниже — вариант «чистый changelog».
2. Снести boilerplate-хвосты: хэш ключа и «нет INTERNET» вынести ОДНОЙ строкой в шапку
   файла как инвариант проекта, из 42 повторов в записях — удалить.
3. Выкинуть все 6 записей `developer-facing` и агентную лексику (`operator`), переписать
   SLOP-заголовки бантиков нейтрально.

агентные артефакты/слоп/ложная нагрузка; P2 — сильное упрощение и унификация; P3 — косметика.

## Читается ли пользователем и предлагаемый формат

**Не читается.** Пользовательский changelog — это `metadata/en-US/changelogs/<versionCode>.txt`
и `metadata/ru-RU/changelogs/<versionCode>.txt` (проверено: 43.txt = 3.6.0, две строки-буллета,
человеческим языком). `CHANGELOG.md` в APK не попадает и на витрину не идёт — он для
разработчика. Значит правильная стратегия — **не пытаться сделать его и тем, и другим**, а
свести к чистому Keep-a-Changelog, а внутреннюю кухню оставить в `HANDOFF.md`/`docs/`.

Предлагаемый формат (Keep a Changelog, один язык — русский):

- Шапка с инвариантами проекта ОДИН раз: офлайн/нет INTERNET, единственное разрешение
  VIBRATE, воспроизводимая подпись. В записях об этом не повторять.
- На версию: 3–6 буллетов, только пользовательский смысл.
- Секции строго `### Добавлено / Изменено / Исправлено / Безопасность / Удалено`.
- Запрещено в записях: хэши, счётчики тестов/правил профиля/итераций, байтовые дельты
  (только «−8,5 %»), коды миссий (SIZE-*, schema N, K/H, LXX, class #, phase, batch, stage),
  ссылки на `docs/`, слова `operator/gate/developer-facing`, пафос-заголовки.

### Пример: 3 переписанные записи

**Было (3.6.0, `CHANGELOG.md:3–8`):**
> ### Changed
> - **The suggestion strip is back to three cells.** The four-cell experiment of 3.3.0 is

## Системные паттерны

1. **Хвост-boilerplate в каждой записи** (ключ подписи ×14, «нет INTERNET» ×~28,
   «словари байт-в-байт» ×~14). Правило: инварианты проекта декларируются ОДИН раз в шапке;
   в записи попадают, только если реально изменились. Массовое удаление ~40+ строк.
2. **`developer-facing` как признак «не сюда».** 6 записей прямо помечены developer-facing;
   плюс всё про CI/гейты/пины/трейсы/тесты/фаззинг. Правило: такой контент живёт в
   `HANDOFF.md`/`docs/`, не в changelog. Grep-маркеры для чистки: `developer-facing`,
   `gate`, `fail-closed`, `CI`, `pin`, `rules)`, `iterations`, `perf ritual`, `PSS`.
3. **Дрейфующие числа.** Счётчики тестов, правил baseline-профиля, итераций фаззинга и
   байтовые дельты APK. Правило: проценты вместо байт, «обновлён профиль» вместо «X → Y
   rules», никаких счётчиков тестов.
4. **Коды миссий и внутренние термины.** SIZE-1/2/3, TATDICT schema 2, TATBIGR schema 3,
   LXX, class #5, phase 4, K/H, batch 1/2, stage D + ~25 ссылок `docs/…`. Правило: перевести
   на язык пользователя или убрать; связку версия↔док хранить в HANDOFF, не в changelog.
5. **Агентная лексика.** `operator/оператор` ×7 — роль из процесса разработки протекла в
   пользовательский текст. Правило: убрать субъекта («оператор решил», «показал оператор»),
   оставить факт.
6. **Пафос-заголовки бантиков.** «Dead machinery removed», «gained real teeth», «test armor»,
   «Proven on-device, not just by manifest», «earns its place». Правило: заголовок буллета —
   нейтральное «что изменилось для пользователя», без метафор.
7. **Двуязычие и разнобой секций.** Файл наполовину RU, наполовину EN; заголовки секций
   в трёх вариантах. Правило: один язык (RU) + фиксированный набор секций Keep a Changelog.
8. **Простыни вместо буллетов.** Абзацы-преамбулы и 7–10-строчные буллеты. Правило: 3–6
   буллетов на версию, один буллет — одна мысль в 1–2 строки.

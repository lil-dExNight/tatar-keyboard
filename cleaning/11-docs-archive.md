# docs/archive/ — ревизия текстов

## Итог

`docs/archive/` — это замороженный «музей миссий»: 439 файлов под git (66 md ≈ 2,5 МБ,
215 tsv ≈ 12,9 МБ, 126 png ≈ 12,5 МБ, плюс 20 txt / 6 py / 3 sh / 3 json), суммарно 28 МБ.
Последняя правка — 2026-09-24 (аудит 3.0.0); архив не редактируется по определению
(так записано в `docs/README.md`), вся история есть в git. Содержательно это на 100 %
закрытые отчёты миссий `tt-*` — ни один не является живым документом. По категориям:
**[DELETE]** — весь каталог кандидат (главная находка); **[SLOP]** ≈ 55 «fail-closed»,
пафосные заголовки-слоганы; **[AGENT]** ≈ 53 строки ритуальной формулы «наружу ничего не
уходило» + 34 шапки «Миссия `tt-…`» + прямые упоминания «агент / суб-агент / досье / живого
телефона у разработчика нет»; **[JARGON]** сплошные коды D0–E5, 1.8.x, tt-* без расшифровки;
**[STALE]** десятки захардкоженных счётчиков тестов и размеров APK (историчны — в архиве
допустимы, но подтверждают «не поддерживается»).

Топ-3 действия:
1. **Удалить бинарно-тяжёлую часть архива** (12,5 МБ png + ~10 МБ tsv-дампов) — её не
   читает ни один живой документ, а история в git. Освобождает ~24 из 28 МБ.
2. **Сохранить единственный load-bearing файл** `dictionary/DICTIONARY-D1A-QUERY-REVIEW.tsv`
   (4 КБ) — его читают 4 JVM-теста в рантайме; при удалении архива его надо перенести в
   тестовые фикстуры (`app/src/test/.../resources/`).
3. **Перед любым удалением** снять ~15 prose-ссылок из живых доков и исходников на
   конкретные файлы архива (список в разделе «Файлы на удаление» и «Системные паттерны»),
   иначе останутся битые ссылки (сборку они не ломают).

Правки текста *внутри* архива (раздел «Правки») имеют низкий приоритет: редактировать
музей смысла нет — либо удаляем/ужимаем целиком, либо оставляем как есть. Приведены
только как доказательство диагноза и как ориентир для будущих *живых* доков.

## Правки (внутри архива — низкий приоритет, приведены как доказательство и ориентир)

Правка музея не имеет смысла (либо удаляем, либо оставляем как исторический слепок).
Ниже — репрезентативные находки, подтверждающие диагноз «нейрослоп», сгруппированные по
типу. Если оператор решит НЕ удалять архив, а ужать до читаемого вида — это точки входа.

### Пафосные заголовки-слоганы [SLOP] — P3

- `bigrams/IMPERATIVE-HEADS.md:1` — [SLOP] — «частые повеления **заговорили, цена названа

- `bigrams/BIGRAM-ADJACENCY.md:1` — [SLOP] — «правило соседства **проверено**, отсечка K

### Ритуальная агентная формула [AGENT] — P1 (если доки останутся)

Паттерн: почти каждый md открывается блоком «Ветка X, база — коммит Y. Наружу ничего не
уходило: ни push, ни тега, ни релиза. Версия не поднималась, keystore не тронут». Это
операционный шум агентной сессии, не содержание. ≈53 вхождения. Примеры:

- `missions/PERSONAL-DICT-FIX.md:3-4` — [AGENT] — «Наружу ничего не уходило: ни push, ни
  тега, ни релиза, ни merge. Ключ подписи не трогался.» → удалить абзац.
- `ux/SMALL-FIXES.md:2-3`, `bigrams/LANG-PRIORITY.md:2-3`, `bigrams/RUSSIAN-BIGRAMS.md:2-4`,
  `dictionary/REVIEW-BATCHES.md:2-3`, `emoji/EMOJI-SEARCH-FIXES.md:2-3` — [AGENT] — тот же

### Коды миссий без расшифровки [JARGON] — P2

Паттерн: заголовки и шапки — сплошь `tt-*`, `D0/D1a-e/D3/E2/E3a/E4/E5a-d`, `1.8.x`,
`versionCode N`, `SIZE-1..3` без пояснения, что это. 34 шапки «Миссия `tt-…`». В архиве
это исторически оправдано, но для читателя со стороны — шум. Примеры: `dictionary/DICTIONARY-D1D.md:1`
(«D1d — bounded mmap prefix engine evidence»), `emoji/DICTIONARY-E2.md:1` («E2a — emoji panel
data asset»), `bigrams/DICTIONARY-E5C.md:1`. → при сохранении добавить в `docs/README.md`
глоссарий кодов; при удалении — неактуально.

### Смешение языков [LANG] — P3

- `bigrams/DICTIONARY-E5C.md:4` — [LANG] — «adds the READ side of **biграм** prediction» —
  латиница+кириллица в одном слове (`biграм`). → «bigram». (Симптом машинной генерации.)
- Массовый паттерн: половина отчётов на русском, половина (D1a-e, E2-E5, E3a) — на
  английском, без причины. Для архива не критично; для будущих живых доков — выбрать один язык.

### Захардкоженные дрейфующие числа [STALE] — P3 (в архиве допустимы как слепок)

Счётчики тестов и размеры APK зашиты в тексте: `missions/PREFIX3-BUG.md:250` («967 JVM-тестов»),
`missions/QUARANTINE.md:24` («913 тестов»), `missions/PERSONAL-DICT-FIX.md:21` («841 тест»),
`missions/MILESTONE-v2.md:75,82,319,573,606` («177 → 186 → 417 → 655 → 685 тестов»,
«1 726 976 из 3 145 728 Б»). Сейчас в проекте 1927 JVM-тестов (AGENTS.md), т.е. все эти
числа устарели. **В архиве это нормально** (историчный снимок) — правка не нужна; отмечено
как индикатор «документ мёртв и не поддерживается». В живых доках такие числа = [STALE]-баг.

## Системные паттерны

1. **Архив = git-дубликат.** 439 файлов, все под version control, каталог не редактируется
   с 2026-09-24 (подтверждено `git log`). Правило: **историю хранит git, не рабочее дерево.**
   Закрытые отчёты миссий не обязаны лежать в репозитории — тег/коммит восстанавливает их
   при надобности. Массовое действие: `git rm -r docs/archive/` с карвинг-аутом Группы 2.

2. **Бинарь и дампы — 90 % веса, 0 % живых ссылок.** 12,5 МБ png + ≈10 МБ tsv-дампов не
   читает ни один живой документ (проверено grep'ом: `archive/.*\.png` в docs = пусто).
   Правило: **свидетельства-скриншоты и сырые дампы корпуса не коммитим** — они
   воспроизводимы скриптом или уже отражены числом в отчёте. Массовое действие: удалить
   все `*.png` и tsv > 100 КБ из архива в первую очередь (максимум освобождённого места,
   минимум риска).

3. **Ритуальная агентная преамбула.** Каждый второй md открывается «Ветка/коммит/наружу
   ничего не уходило/keystore не тронут/версия не поднималась». Это лог агентной сессии, а
   не документация. Правило для будущих *живых* доков: **не описывать операционную гигиену
   сессии в теле документа** — это шум для читателя-человека. Массовая чистка: удалить
   блоки по regex `наружу|ни push, ни тег|keystore не тронут|версия не поднималась`.

4. **Пафос в заголовках.** «Заговорили», «цена названа числом», «доведена до», «правило
   проверено» — заголовок продаёт результат вместо называния темы. Правило: **заголовок =
   тема, а не вывод-лозунг.**

5. **Хрупкие ссылки по номеру строки в огромные файлы.** `docs/archive/PROPOSALS.md:4092` из
   `TT-TYPO-NEXT-PLAN.md` — ссылка на строку в 680-КБ файле. Правило: **ссылаться на
   якорь-заголовок (`## E5`), а не на номер строки.** Это находка и для области живых доков.

6. **Прежде чем удалять — снять входящие ссылки.** Единственный технический риск удаления
   архива: 1 test-critical tsv (перенести в фикстуры) + ~15 prose-ссылок из исходников и
   живых доков (снять/инлайнить). Всё перечислено в Группах 2–3. Массовое действие:
   `grep -rn "docs/archive" app/src docs research CHANGELOG.md`, обработать каждую строку,
   затем удалять.

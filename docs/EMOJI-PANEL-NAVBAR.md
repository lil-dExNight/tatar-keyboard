# EMOJI-PANEL-NAVBAR — панель эмодзи перестала уходить под панель навигации

Дата: 2026-09-04. База: main `63486067` (поверх миссии TABLET-ENTER). Закрывает
дефект **Д-1** из `docs/DEVICE-UAT-1.9.12.md`. Версия НЕ бампалась.

## Что было сломано

На Android 15 нижний ряд панели эмодзи — плавающие клавиши **АБВ** (возврат к
буквам) и **backspace** — рисовался в полосе, которую занимает системная панель
навигации, и нажать их было нельзя:

* тап по видимому центру кнопки не делал ничего — касание уходило системе;
* тап на 20–50 px выше вставлял эмодзи из сетки, лежащей под кнопкой.

Штатного выхода из панели не оставалось (спасало только скрыть и снова открыть
клавиатуру). На Android 14 при **той же** геометрии экрана и той же панели
навигации дефекта не было.

## Расследование

Снаружи причина не читалась: три гипотезы (тип навигации, размер экрана,
плотность) эксперимент отверг — на эмуляторе с трёхкнопочной навигацией и
геометрией, побайтно совпадающей с телефоном (720×1640, density 320, инсет
`[0,1544][720,1640]`), коллизии не было. Поэтому в debug-сборку была временно
добавлена инструментация `InputView.onLayout`, печатавшая реальную геометрию.
Она и дала ответ:

| | Android 15 (POCO C71) | Android 14 (AVD) |
|---|---|---|
| инсет навбара | 96 | 96 |
| `getWindowVisibleDisplayFrame().bottom` | **1544** | **1544** |
| низ `InputView` на экране | **1640** (низ экрана) | **1544** (верх навбара) |
| `EmojiPanelView` | h=580, screenY 1060..1640 | h=524, screenY 1020..1544 |
| `MainKeyboardView` | h=580, screenY 1060..1640 | h=444, screenY 1100..1544 |

Два вывода:

1. **Инвариант, записанный в коде, не нарушен.** Панель и клавиатура занимают
   ровно одну коробку — `InputView.showEmojiPanel` отдаёт панели высоту
   клавиатуры, и это подтверждено замером на обеих платформах. Ранняя оценка
   «панель на 40 px короче», сделанная по скриншоту, была неверной.
2. **Различается платформа.** До Android 14 включительно система сама
   раскладывала input view выше панели навигации; с Android 15 — нет, и
   последние 96 px окна оказываются под баром.

Почему буквенная клавиатура при этом цела: её ряды не заполняют свою коробку —
нижняя точка пробела измерена по пикселям на `y = 1531` при коробке до `1640`,
то есть ~109 px запаса. Этого случайно хватает, чтобы перекрыть 96 px навбара.
Это **запас, а не инсет**: на устройстве с более высоким баром или при другой
высоте клавиатуры клавиши уехали бы туда же.

Панель же прибивает плавающие клавиши к нижнему краю своей коробки:

```kotlin
fun floatingBottom(): Int = panelHeight - floatingInsetPx        // 8dp
fun floatingTop():    Int = panelHeight - floatingInsetPx - floatingPx  // 44dp
```

При `panelHeight = 580` и коробке 1060..1640 это даёт 1536..1624 при навбаре
1544..1640 — 80 из 88 px кнопки внутри бара. Ровно то, что видно на снимках.

## Решение

Панель получила понятие «низ используемой области»:

```kotlin
private fun usableHeight(): Int = (panelHeight - bottomInsetPx).coerceAtLeast(0)

fun gridHeight():     Int = (usableHeight() - gridTop()).coerceAtLeast(0)
fun floatingTop():    Int = (usableHeight() - floatingInsetPx - floatingPx)…
fun floatingBottom(): Int = (usableHeight() - floatingInsetPx)…
```

Через одну точку проходит всё, что означает «низ панели», поэтому вместе
поднимаются отрисовка, **touch-цели** (хит-тест читает те же два числа),
прокручиваемая область и границы узлов доступности.

`bottomInsetPx` измеряет сама вью, в `onLayout`, где обе величины окончательны:

```kotlin
getWindowVisibleDisplayFrame(visibleFrameScratch)
getLocationOnScreen(locationScratch)
val overlap = locationScratch[1] + height - visibleFrameScratch.bottom
state.setBottomInset(overlap.coerceAtLeast(0))
```

**Почему `getWindowVisibleDisplayFrame`, а не `WindowInsets`.** Инсет навбара
обе платформы репортят одинаково (96), поэтому по нему их не различить — окно
IME на обеих доходит до низа экрана, различается лишь раскладка контента внутри.
`getWindowVisibleDisplayFrame` даёт одинаковый низ (1544 = верх бара) на обеих,
и разность с фактическим низом вью и есть настоящее перекрытие: **0 на
Android 14, 96 на Android 15**. Один вызов, доступный с API 1, без ветвлений по
версии и без чтения метрик дисплея (`displayMetrics.heightPixels` для этого
непригоден: на A15 он вернул 1640, на A14 — 1453).

**Почему не общий инсет на весь `InputView`.** Это выглядит правильнее, но
сломало бы клавиатуру: её коробка ушла бы вверх на 96 px вместе с её же
109-пиксельным запасом, и между клавишами и баром появилась бы пустая полоса.
Клавиатура сегодня выглядит верно на обеих платформах — трогать её незачем.
Правка локальна ровно там, где поведение неверно.

Аллокаций починка не добавляет: `Rect` и `IntArray(2)` заведены полями и
переиспользуются, замер идёт в `onLayout`, а не в цикле отрисовки.

## Тесты

Пять тестов в `EmojiPanelStateTest` (всего в файле 40):

* инсет поднимает плавающие клавиши и ужимает вьюпорт на ту же величину;
* низ клавиш не заходит в полосу инсета;
* нулевой инсет оставляет геометрию ровно прежней;
* повтор того же значения не считается изменением (лишней перерисовки нет);

## Проверка на устройствах

**POCO C71 / Android 15** (там, где дефект найден): кнопки АБВ и backspace
поднялись над панелью навигации, сетка эмодзи тоже останавливается выше
(`device-uat/evidence/18-fix-emoji-panel-above-navbar.png`); тап по АБВ
**возвращает к татарским буквам** — штатный выход из панели работает
(`19-fix-abv-returns-to-letters.png`).

**AVD / Android 14**: панель выглядит в точности как до починки — перекрытие
считается нулём, ничего не сдвинулось (`20-fix-android14-unchanged.png`).

Проверка велась debug-сборкой (пакет `…ime.debug`), поэтому релизный артефакт на
телефоне не затрагивался; после прогона debug-пакет удалён, IME возвращён на
релизный. Сверено: на телефоне по-прежнему побайтно
`dist/tatar-keyboard-1.9.12.apk` (`6d0038a1…`).

Временная инструментация `InputView` снята (`git checkout`), файл в дереве
не изменён.

## Что не изменилось

* Буквенная клавиатура — ни на одной платформе;
* панель эмодзи на Android 14 и ниже — перекрытие там ноль;
* ландшафт — навбар уходит вбок, перекрытия снизу нет и не было;
* словари, таблицы биграмм, эмодзи-ассеты, разрешения, подпись, versionCode 28.

## Осталось открытым

* **Запас клавиатуры остаётся случайным.** Она цела потому, что её ряды не
  заполняют коробку, а не потому, что кто-то зарезервировал бар. На устройстве с
  более высоким навбаром это может не сработать. Отдельного дефекта нет —
  зафиксировано как наблюдение.
* **Версия не бампалась**; публикация — решение оператора.

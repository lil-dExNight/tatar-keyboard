# Apple-like UX: current-state audit and implementation plan

Date: 2026-09-25. Base: `main` @ `bd786a13` (post-3.0.2 tree).
Scope: app screens (settings/setup), keyboard theme, suggestion strip, emoji panel, typography, radii, spacings, animations, haptics — measured against the iOS references.

## 0. Sources

- `research/04-stil-apple.md` (2026-07) — iOS keyboard geometry, KeyboardKit palette, haptics/sound mapping, legal boundaries (SF Pro / SF Symbols bans, trade-dress analysis).
- `docs/archive/ux/IOS-REDESIGN.md` — the executed redesign plan: waves **D** (app design tokens + SetupActivity), **S1/S2** (settings screens on classic Views) are **done**; wave **K** (keyboard skin behaviour, items K1–K6) was **cancelled by operator decision 2026-07-20** and is preserved as reference. External references (re-verified 2026-09-25):

- [KeyboardKit Colors.xcassets (master)](https://github.com/KeyboardKit/KeyboardKit/tree/master/Sources/KeyboardKit/Resources/Colors.xcassets) — fetched raw: background light sRGB 0.835/0.839/0.867 = **#D5D6DD**, dark **#2C2C2C**; key shadow **black α 0.30 light / 0.70 dark**; functional key light **#ABB1BA**, dark **#474747** (the project's `#B3B7C0` matches the older 6.9.4 pin).

- [learnui.design — iOS 26 Design Guidelines](https://www.learnui.design/blog/ios-design-guidelines-templates.html) — current text styles (Large Title 34pt bold, list cell 17pt regular, secondary 15pt `#3C3C43`@60%, caption 13pt), 44pt tap targets, iOS 26 "more rounded corners" + Liquid Glass reserved for the navigation layer (lists unchanged).
- [Apple HIG — Onscreen keyboards](https://developer.apple.com/design/human-interface-guidelines/onscreen-keyboards) and [HIG — Settings](https://developer.apple.com/design/human-interface-guidelines/settings) (JS-walled pages; cited as canonical anchors — no numeric specs are published there).
- OSS approaches: [FlorisBoard](https://github.com/florisboard/florisboard) themes are declarative Snygg stylesheets (per-element background/foreground, corner radius, shadow, font) shipped as `.flex` extensions; community packs ([itsmartashub/floristyle](https://github.com/itsmartashub/floristyle)) replicate Gboard/iOS looks purely as data — validation that this project's "theme = resources, zero code" approach is the right layer. KeyboardKit is the Swift reference implementation whose colour assets the project already mirrors.

### 1.2 Drift vs the reference (each with file:line)

**Keyboard (all but #9 trace to the cancelled wave K of `docs/archive/ux/IOS-REDESIGN.md`):**

1. **Key shadow too weak in light mode** — `#40000000` (α 0.25) vs the reference α 0.30. Dark `#B3000000` (0.70) already matches. `values/colors.xml:35`. (K5 residue.)
2. **Functional-key grey is the old pin** — `#B3B7C0` vs KeyboardKit master's current `#ABB1BA`. `values/colors.xml:30`. Minor.
3. **Shift has two visible states, iOS has three** — one-shot shift and caps-lock render the *same* icon: `shift_key_shifted` maps to `sym_keyboard_shift_locked` (filled arrow **with** the bar) for both, `key_styles_common.xml:53,62` + `KeyboardIconsSet.java:78`. iOS: off = outline arrow on grey; shifted = **filled arrow without bar on a white key**; caps = filled arrow with bar on white. The white-key inversion is also missing: stickyOn fill is `ios_key_checked` `#A2A6B0`, `values/colors.xml:32`. (K2.)
4. **Letter keys darken on press** (`ios_key_normal_pressed` `#C8CDD4`, `values/colors.xml:29`, selector item in `drawable/ios_key_normal.xml:36-51`). iOS letters give press feedback *only* via the balloon. (K3.) **Conflict:** the P7-5 glide key-highlight rides the same `onKeyPressed` path (commit `0654ed4f`, `PointerTracker.java` → `sDrawingProxy.onKeyPressed(key, false)`), so deleting the pressed state would kill the glide highlight too.
5. **Spacebar language label fades to α 128** — `config_language_on_spacebar_final_alpha = 128`, `values/config-common.xml:41` (wired at `themes-common.xml:59`). iOS keeps the spacebar label constant. (K4.)
6. **Balloon is a plain rectangle, not the droplet** — 45dp wide, 5dp corners, geometry mirrored from the legacy feedback background (`drawable/ios_key_preview_background.xml:30-38`; `config.xml:56-58`: offset 55dp, height 122dp). iOS balloon: ~53dp wide, larger top radius, a "neck" flowing into the key, asymmetric at screen edges. (K6.)
7. **More-keys panel is grey-on-grey** — panel fill `ios_keyboard_background_secondary` `#C7CAD2` (`themes-tatar.xml:30`), selection `ios_popup_key_pressed` `#A2A6B0` (`values/colors.xml:38`). iOS: white panel (dark: key grey), selected item accent-blue with white glyph. (K1.)
8. **Enter/action key never gets the accent treatment** — `BACKGROUND_TYPE_ACTION` resolves to the *normal* key background with `state_active` (`Key.java:872-873,884-898`), and `ios_key_normal.xml` has no `state_active` item, so Return renders as a plain white key. iOS paints an actionable Return blue with white label.
9. **Haptics bypass the system toggle on API < 29** — `performHapticFeedback` passes `FLAG_IGNORE_GLOBAL_SETTING` (`AudioAndHapticFeedbackManager.java:127-131`). The iOS-faithful behaviour (and the API 29+ branch here) is to respect the user's global haptics switch.

**Suggestion strip:**

10. Strip is 40dp vs iOS's ~44–45pt (`SuggestionStripState.kt:161`, `input_view.xml:35`); cell text 17dp vs ~18pt (`SuggestionStripView.kt:550`).
11. Separators run edge-to-edge (`drawLine(x, 0f, x, height)` at `SuggestionStripView.kt:299-302`); iOS hairlines are vertically inset (~20% margins). Pressed feedback is a full-cell square rect (`SuggestionStripView.kt:283-292`); iOS uses an inset rounded (~4–5pt) rect.

**Deliberate deviations (documented, keep):** the emoji panel is the operator-requested Telegram arrangement (top tabs + search pill + floating corner keys — `EmojiPanelView.kt:49-56`), not the iOS paged panel; settings dialogs stay platform `DeviceDefault` (`platform-theme.xml:23`) — accepted in IOS-REDESIGN S2.1; the setup screen uses system `textAppearance*` for step text rather than `AppText.*` — consistent enough in practice.

**W2 — Functional key `#B3B7C0` → `#ABB1BA` (light).** One line, `values/colors.xml:30`. Optional: this re-pins to KeyboardKit master; the delta is subtle. *Check:* visual A/B screenshot only.

**W3 — Spacebar label α 128 → 255.** One line, `values/config-common.xml:41`. The language label stops fading while typing. *Check:* type five chars on the tt layout in the smoke test; the spacebar label stays fully opaque in the screenshot diff.

**W5 — Strip height 40 → 44dp.** Two lines (`SuggestionStripState.kt:161`, `input_view.xml:35`). **W6 — Respect the global haptics setting on API < 29.** Remove `FLAG_IGNORE_GLOBAL_SETTING` (`AudioAndHapticFeedbackManager.java:130`). One line; minSdk-24 behaviour aligns with the API 29+ branch and with iOS's "haptics off by default" spirit. *Check:* existing JVM contract tests for the class; manual: system haptics off → no vibration on key press.

## 3. What NOT to copy from Apple

- **SF Pro, SF Symbols, Apple key-click sounds** — licence-prohibited outside Apple platforms (`research/04-stil-apple.md` §9). Keep Roboto (`Typeface.DEFAULT`) and the hand-drawn VectorDrawable icons.
- **Liquid Glass / real-time blur in the IME window (iOS 26)** — translucency costs GPU on budget devices, conflicts with the "zero allocations in the draw loop / cold start < 400ms" budgets, and buys nothing offline. Keep the opaque classic palette.
- **iOS 26's same-colour system+input keys and bolder key letters** — on the 11–12-key Tatar Cyrillic rows the grey/white split between letters and functional keys is a load-bearing orientation cue; merging them would regress usability. Target the classic iOS 7–18 look the BRIEF pins.
- **iOS's 6pt fixed horizontal gaps** — unaffordable at 12 keys/row; the current fraction-based gaps (`config.xml:52-53`) are the right adaptation.
- **The paged iOS emoji panel** — the operator chose the Telegram arrangement; do not reopen.
- **Large-title collapse animations, parallax icons, per-key haptic waveform compositions** — outside the product's character and budgets; `EFFECT_CLICK`/`KEYBOARD_TAP` is the right ceiling.
- **"iOS keyboard" marketing wording** — trademark/impersonation risk in stores (research doc §9); the app describes itself as a "minimalist light style".

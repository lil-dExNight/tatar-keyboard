## A. Свежие находки волны 3.3.0 (2026-09-27/28)

1. **Генератор baseline/startup-профилей сломан для текущего UI.**
   `ImeBaselineProfileGenerator.ensureSuggestionsEnabled` ищет строку настроек
   по тексту («Preferences»), а с 3.1.0 UI по умолчанию татарский —
   `IllegalStateException: Preferences row not found`. Дополнительно генератор
   выбрал подключённый телефон вместо эмулятора. Релиз 3.3.0 вышел с профилем
   от 2026-09-25. Фикс: селекторы по resource-id вместо текста + явный выбор
   устройства (пин на эмулятор) в `baselineprofile/`.
2. **`GlideUiDeviceTest` виснет при классовом прогоне** (оба метода сразу):
   второй `prepareField` ждёт поднятия IME, которое уже поднято от первого.
   По одному методу — зелёные на POCO. Разобрать харнесс (вероятно, переиспользование
   состояния активити между методами).
3. **`GlideUiDeviceTest` на чужой геометрии виснет, а не падает.** Координаты
   жёстко под 720×1640 (POCO); на эмуляторе 1080×2280 — 30-минутное зависание.
   Нужен fail-fast гард по размеру экрана (или skip) в начале класса.
4. **Дрейф комментариев:** `SuggestionsController.kt` — «reserved 40dp» при
   фактических 44dp; `AGENTS.md` — известный дрейф «татарская 3/0», фактически
   155/0 (`scripts/known_asset_drift.json`); `docs/ROADMAP-P7.md` — линия
   «p95 50,03 мс против гейта» не закрыта сноской: замер 3.3.0 на POCO C71 дал
   **p95 = 3,083 мс, PASS** (устройство было разгружено; вопрос P7-4 снят).
5. **Наблюдение о платформе (не наш код):** HyperOS при force-stop дефолтного
   IME молча переключает систему на другую клавиатуру — учитывать в тестовых
   циклах (не force-stop'ать пакет, чей IME выбран).

## B. Технический долг (по убыванию ценности)

1. **`RichInputMethodManager.java:787`** — `switchToTargetIme` создаёт новый
   single-thread executor на каждый вызов без shutdown: тихая утечка потоков
   при частом переключении через пикер.
2. **Тап по эмодзи-ячейке полосы не пишется в recents** — запись есть только у
   панели и поиска (`KeyboardSwitcher`). Асимметрия: из кода не читается,
   осознанно ли. Если случайно — тривиальный фикс; если нарочно — записать
   причину в код.
3. **Потолок `EmojiSuggestIndex` 4096 записей при shipped 3976** — запас <4 %.
   Шардирование отклонено замером (557 КБ resident, opt-in, idle-release),
   значит при росте таблицы: либо поднять потолок с ритуалом перемерки, либо
   резать хвост по частоте.
4. **Латентностные device-«гейты» наблюдательные** (E3b, GlideDevice пишут
   verdict в лог, но не assert'ят) и instrumentation не гоняется в CI вообще.
   Вариант: assert с консервативным порогом на p95 + документированный ритуал
   прогона.
5. **`shrinkResources` без автоматического стража** при пустом
   `proguard-rules.pro` — защита только смоуком/UAT. Вариант: гейт,
   перечисляющий критичные ресурсы в APK (как artifact.tree_assets для ассетов).
6. **`KeyboardTextsTable` правится вручную** — генератор утерян; добавление
   локали требует синхронной правки таблицы и `SubtypeLocaleUtils`.
7. ~600 строк мёртвого класса #5 в `TdictPrefixIndex` (документированный
   NO SHIP — калибровочное свидетельство; компилируется, тестируется, не
   подключён). Держать или удалить — решение осознанное; сейчас — держать.
8. `release_check.sh` резолвит build-tools по «старшим», `release_pack.sh`
   пинит 37.0.0 — привести к одному источнику.
9. `verification-metadata.xml` — trust-on-first-record (чексуммы без подписей).
   Усиление: подписи или ключ-файл, если захочется строже.

## C. Новая фича: эмодзи, выученные по сочетаниям пользователя

**Запрос оператора (2026-09-28):** сейчас после набора «хәйерле иртә» полоса
предлагает один статический смайлик (🌅). Если пользователь всегда ставит
другой (☀️), клавиатура должна это запоминать и предлагать ЕГО в следующий раз.

**Текущая механика:** `EmojiSuggestIndex` — статическая таблица (lang, word) →
emoji (`emoji_suggest_v1.txt`, ~3 976 записей), хвостовая ячейка
NEXT_WORD-полосы; свой тоггл (`pref_emoji_suggestions`, по умолчанию ON, под
мастером подсказок).

**Дизайн-набросок (под существующую архитектуру):**

- **Хранилище:** личная карта `normalizedWord → emoji`, per язык, с счётчиком
  использований. Формат — как у личных пар (fail-closed валидатор, атомарная
  запись, `noBackupFilesDir`, солёные pending-хэши до порога), НО эмодзи не
  проходят алфавитный фильтр слов — отдельный маленький файл (например
  `.tpersem`) или расширение формата пар. Кап ~500 записей, LRU по serial.
- **Обучение:** событие «после закоммиченного слова пользователь вставил
  эмодзи» (из панели, поиска или чужой вставки? — только панель/поиск/тап по
  полосе, т.е. наши собственные вставки; вставка из буфера не учится — правило
  как у CleanRunMachine). Порог как у пар: с 2 наблюдений выученный эмодзи
  лидирует в хвостовой ячейке ЭТОГО слова, отодвигая статический. Мульти-эмодзи
  кластер (☀️😊) записывается целиком (логика кластеров уже есть в
  `EmojiTextUtils`).
- **Ранжирование:** слой перекрытия поверх статической таблицы: сначала
  выученное, потом статическое; два разных выученных — по счётчику. Никогда не
  автовставлять — только предложение.
- **Гейты:** мастер подсказок → тоггл эмодзи-подсказок → личный словарь ON →
  инкогнито OFF (пауза обучения, чтение продолжается) → разблокировка. Всё как
  у личных слов/пар.
- **UI:** экран «Шәхси сүзлек» получает третий список (или пары-экран
  расширяется): выученные эмодзи с счётчиками, forget/очистка. FLAG_SECURE уже
  на месте.
- **Тесты:** формат fail-closed, порог обучения, перекрытие статики, кап/LRU,
  инкогнито, забвение; e2e контроллера; device-нога: добавить, выбрать ☀️ дважды
  после «хәйерле иртә», увидеть ☀️ первым.
- **Чего НЕ делать:** не учить по словарным словам автозамену эмодзи; не
  вытеснять статический ряд полностью (выученный — только лидер ячейки); не
  писать ничего при выключенных тогглах; не пускать чужой буфер обмена.

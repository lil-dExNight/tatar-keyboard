# TABLET-ENTER — клавиша Enter вернулась в кириллические раскладки на планшетах

Дата: 2026-09-04. База: main `63486067`. Закрывает дефект **Д-2** из
`docs/DEVICE-UAT-1.9.12.md`. Версия НЕ бампалась — решение релизной миссии.

## Что было сломано

При smallest width ≥ 600 dp (планшеты, крупные раскладные в портрете) у раскладок
**tatar и russian клавиши Enter не было вообще** — ни в одном ряду. Отправить
сообщение или submit формы такой раскладкой нельзя. Английская QWERTY при той же
геометрии работала.

Дефект существовал с момента появления татарской раскладки и не мог быть найден
ни в одном отдельно взятом файле: неправильна была только **разрешённая
комбинация** ресурсов.

## Диагноз

```
xml/rows_tatar.xml            → include @xml/row_qwerty4      (Enter приходил отсюда)
xml/rows_russian.xml          → include @xml/row_qwerty4

xml/row_qwerty4.xml           → …, Key enterKeyStyle fillRight        ← телефон, Enter есть
xml-sw600dp/row_qwerty4.xml   → …, Spacer 9%p                         ← планшет, Enter НЕТ

xml-sw600dp/rows_qwerty.xml   → второй ряд: Key enterKeyStyle fillRight ← QWERTY забрала Enter себе
xml-sw600dp/rows_tatar.xml    → НЕ СУЩЕСТВУЕТ  ─┐ обе берут базовые rows_*.xml,
xml-sw600dp/rows_russian.xml  → НЕ СУЩЕСТВУЕТ  ─┘ где enterKeyStyle не встречается ни разу
```

Планшетный нижний ряд кончается `<Spacer>` потому, что планшетная QWERTY уносит
Enter во второй ряд собственным `rows_qwerty.xml`. Каждая латинская раскладка
получила планшетный `rows_*.xml` (abc, azerty, colemak, dvorak, qwerty, qwertz,
workman) — **обе кириллические, добавленные этим проектом, не получили**. Они
продолжали брать базовые файлы, у которых Enter жил только в общем нижнем ряду,
а на планшете он там превращался в распорку.

## Решение

Заведён собственный нижний ряд кириллических раскладок:

| Файл | Содержимое |
|---|---|
| `xml/row_cyrillic4.xml` (новый) | делегирует `@xml/row_qwerty4` — на телефоне поведение бит-в-бит прежнее |
| `xml-sw600dp/row_cyrillic4.xml` (новый) | планшетный `row_qwerty4`, где `<Spacer>` заменён `Key enterKeyStyle fillRight` |
| `xml/rows_tatar.xml` | include переставлен на `@xml/row_cyrillic4` |
| `xml/rows_russian.xml` | то же |

**Почему Enter в нижнем ряду, а не во втором, как у планшетной QWERTY.**
Перенос в ряд выше потребовал бы завести полные планшетные `rows_tatar.xml` и
`rows_russian.xml` — второй экземпляр раскладки, который неизбежно разойдётся с
первым (ровно тот класс ошибки, из-за которого дефект и возник). Нижний ряд
оставляет одну точку правды на буквенные ряды и сохраняет телефонную мышечную
память. Если оператор захочет планшетную эргономику AOSP — это отдельное
решение, оно потребует именно тех двух файлов.

**Почему делегирование, а не копия телефонного ряда.** Копия дала бы второй
экземпляр нижнего ряда, который тоже может разойтись. `<include>` внутри
`<merge>` на уровне рядов парсер поддерживает рекурсивно
(`KeyboardBuilder.parseIncludeKeyboardContent` → `parseMerge` →
`parseKeyboardContent`), так что делегирование ничего не стоит.

**Ширины не пересчитывались.** Инвариант планшетного ряда записан в
`key_space_7kw.xml`: `10 + 9 + [63] + 9 + 9 = 100 %p`. Enter занимает ровно те
9 %p, что были у `<Spacer>`, через `fillRight`. Фон клавиши задаёт её
собственный стиль (`defaultEnterKeyStyle`, `backgroundType="action"`), поэтому
`functional`-фон ряда на неё не распространяется — Enter выглядит так же, как на
телефоне.

## Тест

Новый `app/src/test/.../keyboard/EnterKeyPresenceTest.kt` (4 теста) пинит не
частный случай, а инвариант: **у каждой отгружаемой раскладки (tatar, russian,
qwerty) должны быть Enter, delete и shift на каждом классе экранов**. Тест
разрешает `@xml/`-include'ы так же, как это делает система ресурсов, включая
приоритет qualifier'ов (smallestWidth старше ориентации, поэтому планшет в
ландшафте предпочитает `xml-sw600dp`, а не `xml-land`).

Красный → зелёный проверен откатом починки:

```
БЕЗ починки: EnterKeyPresenceTest > everyShippedLayoutHasEnterAtEveryBucket FAILED
  нет клавиши Enter: tatar / планшет, портрет; tatar / планшет, ландшафт;
                     russian / планшет, портрет; russian / планшет, ландшафт
             EnterKeyPresenceTest > cyrillicLayoutsUseTheirOwnBottomRow FAILED
С починкой:  тестов 4, падений 0
```

QWERTY в списке падений отсутствует — тест воспроизводит диагноз точно.

Оговорка: тест читает `res/` с диска напрямую (как и `SpaceKeyLayoutTest`),
поэтому Gradle не видит эти файлы во входах задачи и не перезапускает тест при
правке одних только ресурсов. Для честной проверки нужен `--rerun-tasks`;
в CI он и так выполняется на чистом дереве.

Комментарий `SpaceKeyLayoutTest` дополнен: список файлов, включающих
`key_space_7kw.xml`, теперь упоминает и `row_cyrillic4`.

## Проверка на устройстве

Эмулятор `tt_suggest_a14` с планшетной геометрией (`wm size 1200x1920`,
`wm density 320` → smallest width 600 dp), релизная сборка с починкой:

* татарская — Enter в нижнем ряду справа от точки
  (`device-uat/evidence/15-fix-tablet-tatar-enter.png`);
* русская — то же (`16-fix-tablet-russian-enter.png`);
* английская — **не изменилась**, Enter по-прежнему во втором ряду;
* Enter работает, а не просто нарисован: в поле SMS вставился настоящий перевод
  строки (`17-fix-enter-inserts-newline.png`);
* телефонная геометрия (1080×2280) — нижний ряд бит-в-бит прежний:
  `?123 , 🌐 [русский] . ↵`.

Телефон оператора не трогался: там лежит побайтно тот артефакт, который поедет
в стор.

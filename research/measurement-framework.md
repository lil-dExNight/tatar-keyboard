# Measurement framework

How this project proves that a change is an improvement. Every research proposal in this
directory must name the metric it moves and the harness that measures it. A proposal without
a measurable gate is an idea for `docs/BACKLOG.md`, not work for the roadmap.

## Principles

- Pre-registered gates. The pass threshold is written down before the experiment runs.
  Precedents: the imperative-heads selection rule was written before measuring; the glide
  context rerank patch measured below its decision rule and stayed parked in
  `docs/BACKLOG.md`.
- Train/held-out discipline. Nothing is tuned on held-out data. Splits are deterministic:
  a SplitMix64 hash of the word decides its side, so Python and Kotlin agree bit for bit.
- Timings are measured on the reference device, never on CI hosts or emulators. Debug numbers
  never close or break a release budget. The rules live in `docs/PERF-BUDGETS.md`.
- Size and artifact regressions are checked by `scripts/release_check.sh`, not by inspection.
- No telemetry. The keyboard has no INTERNET permission, so all quality evidence comes from
  offline corpora, lab sessions and device scripts.

## The harness today

Quality:

- Completion and next-word accuracy: `scripts/suggest_eval.py` and its JVM mirror
  `TtSuggestEvalTest` on the pinned held-out Tatar sentence set
  (`app/src/test/resources/tt_eval_sentences.txt`); `RuSuggestEvalTest` measures the Russian
  engine the same way on `app/src/test/resources/ru_eval_sentences.txt`. They report top-3
  hit rates.
- Typo recovery: edit-class sets generated by `scripts/typo_pack.py`, pinned identically in
  `tests/typo_pack/` and `E3aRecoveryCalibrationTest`; device latency asserted by
  `E3bComputeInstrumentationTest`.
- Glide decoding: the synthetic gesture set from `scripts/glide_pack.py`, regenerated bit for
  bit by `GlideRecoveryCalibrationTest` (held-out accuracy gate, host p95 gate skipped under
  CI, allocation gate, per-class tolerances for plain, doubled and alias gestures); device
  checks in `GlideDeviceInstrumentationTest` and `GlideUiDeviceTest`.
- Engine latency: host p95 gates in `RealDictionaryPrefixIndexTest` and
  `TtNextWordPredictP95Test`; device p95 in the instrumentation tests.

Performance and footprint:

- `scripts/device-perf-ritual.sh` legs: cold, pss, frames, warm, touch, suggest (opt-in:
  battery, uimode, fontscale). Budgets are constants in the script; `docs/PERF-BUDGETS.md`
  defines the measurement rules.
- Zero allocations in the draw loop: `DrawAllocInstrumentationTest`, backed by source
  contracts such as `KeyboardViewDrawLoopContractTest`.
- APK size and asset budgets: `scripts/release_check.sh` (`artifact.size`) and the byte
  budgets inside `scripts/*_pack.py`.

Data correctness:

- `scripts/rebuild_assets.py --check --allow-known-drift` against the pins in
  `DictionaryStorageContracts.kt` and `BigramStorageContracts.kt`, with the known-drift
  counts in `scripts/known_asset_drift.json`.
- Validator fuzz tests for every binary format.

## Gaps this research program must close

1. No corpus of real user gestures exists (offline by design); glide calibration is
   synthetic. The glide research must propose a privacy-preserving collection protocol.
2. No user-level metric is computed (keystroke savings, correction rate); the eval harness
   reports hit rates only.
4. Companion-language behavior (one language filling another language's empty strip cells)
   has no eval coverage.
5. `docs/BACKLOG.md` carries measured rejections (trigram prediction, two-edit typo
   recovery, geometric-neighbor typo recovery, wider autocorrect, emoji index sharding).
   Reopening one requires new data, not a rerun of the same experiment.

## Writing a decision memo

Each research document ends with proposals in this shape: what changes; the metric it must
move; the gate (threshold and harness, written down before the experiment); the budget cost
(bytes, milliseconds, PSS); the fallback if the gate fails.
